# Coverage matrix — Group 1 discovery vs. Group 2/3 implementation

Rebuild of `docs/rebranding.md` §19's 45-area coverage matrix, requested as part of the F4 Phase 4/5
readiness deliverable set (`docs/RebrandingPlan.md` §7.1). This document has two purposes that must
not be conflated, per the task that produced it:

- **"Group 1 discovery status"** — was the *discovery/audit* for this area complete? This is a fact
  about `docs/rebranding.md` as a certified artefact and is **not re-verified here**; it is carried
  forward unchanged (it is what the original `VC`/`SPC`/`IDA`/`BLD`/`OOS` column in
  `docs/rebranding.md:1519-1573` already certifies, and re-auditing it is out of scope for this
  document).
- **"Phase 2/3 implementation status"** — has the branding module (built this session, now committed
  as `a1c22b6a1`..`c6c3f9e6e` on `feat/thiqa-branding-foundation`) actually implemented what the area
  needs, and is there evidence of that beyond the plan's intent? This is what this document adds.

**Evidence rule.** Every "implementation status" cell is backed by a citation — either a file:line
read directly in this session, a command run in this session, or a specific line in
`docs/AuditRebranding.md` (itself an evidence-bearing document, not a claims document — its own
entries carry file:line/command citations). Where no such evidence exists, the cell says so plainly
rather than inferring completion from the plan's design intent. This mirrors `docs/rebranding.md`
§18's corrections-register culture: a claim that outruns its evidence is worse than an admitted gap.

Statuses carried from the original matrix: **VC** = Verified Complete · **SPC** = Source-Proven
Complete · **IDA** = Implementation-Dependent Acceptance · **BLD** = Blocked by Locked Decision ·
**OOS** = Out of MVP Scope. These describe **discovery** completeness only, exactly as
`docs/rebranding.md` defined them — do not read a `VC` in the second column as "the feature is
finished."
