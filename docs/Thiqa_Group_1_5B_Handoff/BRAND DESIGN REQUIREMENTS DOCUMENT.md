# BRAND DESIGN REQUIREMENTS DOCUMENT
## OpenEMR-Based Saudi SaaS HIS — Complete Visual Identity Design Specification

**Document Type:** Brand Design Requirements / Design Contract  
**Purpose:** Produce the complete visual identity package required before Group 2 Branding Implementation  
**Downstream Consumer:** Group 2 Branding Layer Implementation  
**Product Category:** Healthcare Information System (HIS) / Electronic Medical Record (EMR) / Healthcare SaaS  
**Primary Market:** Saudi Arabia  
**Languages:** Arabic + English  
**UI Direction:** RTL + LTR  
**Theme Requirement:** Light + Dark  
**Design Status:** NEW BRAND — do not reproduce OpenEMR visual identity

---

# 1. OBJECTIVE

Design a complete, professional, production-ready visual identity for a modern Saudi healthcare SaaS/HIS product built on OpenEMR.

The resulting brand system must be suitable for:

- hospitals;
- medical centers;
- polyclinics;
- clinics;
- physicians;
- nurses;
- reception staff;
- accountants;
- administrators;
- healthcare executives;
- insurance/RCM users;
- patients through the Patient Portal;
- external healthcare integrations;
- FHIR/SMART applications;
- web marketing;
- printed/PDF healthcare documents.

The design must communicate:

- healthcare;
- trust;
- safety;
- technology;
- accuracy;
- professionalism;
- modern SaaS;
- enterprise readiness;
- Saudi-market suitability;
- bilingual Arabic/English capability.

The identity must NOT visually imitate OpenEMR.

The identity must be capable of replacing all user-visible OpenEMR branding identified during Group 1 discovery.

---

# 2. DESIGN-AUTONOMY RULE

The designer/AI MUST NOT stop and ask the user routine design questions.

The designer is explicitly authorized to make professional design decisions where this specification does not prescribe an exact value.

Examples include:

- exact geometric construction of the symbol;
- precise spacing;
- optical corrections;
- corner radii;
- secondary shades;
- typography sizing ratios;
- logo lockup spacing;
- icon stroke thickness;
- exact neutral palette;
- contrast adjustments.

When multiple valid alternatives exist:

1. choose the strongest enterprise-healthcare option;
2. document the choice;
3. maintain consistency across the entire system.

Do NOT leave unresolved placeholders such as:

`TBD`

`Choose later`

`Ask client`

unless the information fundamentally requires a business/legal decision such as the final registered product name or actual domain.

# 13. FILE FORMAT POLICY

MASTER SOURCE:

SVG.

Raster delivery:

PNG with transparency.

Legacy only:

GIF.

Browser compatibility:

ICO.

Do NOT use JPG for logos unless an unavoidable downstream surface requires it.

SVG files must:

- contain valid vector paths;
- scale cleanly;
- contain no rasterized embedded logo image;
- avoid unnecessary metadata;
- use a sensible viewBox;
- avoid external dependencies.
